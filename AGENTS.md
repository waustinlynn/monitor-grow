# AGENTS.md

Repository-specific engineering, architecture, and testing standards for automated coding (`agentic-coder[bot]`) and review (`agentic-reviewer[bot]`) agents working on **monitor-grow**.

## Product Overview

**monitor-grow** is a low-cost, serverless web application for monitoring a grow setup (temperature and humidity telemetry):
- **Phase 1 (MVP):** Go HTTP API (`chi` + `Huma v2`) on AWS Lambda + HTTP API Gateway v2, DynamoDB On-Demand persistence, EventBridge 1-minute scheduled alerting Lambda (missing-reading heartbeat alerts & rolling-window out-of-range average alerts), and AWS SNS notifications.
- **Phase 2:** TypeScript React SPA (`Vite` + `openapi-fetch` + `TanStack Query`) hosted on S3 + CloudFront displaying historical telemetry charts and managing alert rules.

## Architectural Principles

1. **Ports-and-Adapters (Hexagonal) Backend:** HTTP handlers in `backend/internal/api/` and domain services in `backend/internal/domain/` MUST depend only on domain port interfaces (`TelemetryRepository`, `AlertRuleRepository`, `AlertNotifier`, `Clock`, `Authenticator`, `HealthChecker`), never directly on DynamoDB or SNS SDK clients.
2. **Zero-Docker Local & Agent SDLC:** Never require Docker, Docker Compose, or `testcontainers` in `justfile`, Go tests, or Node scripts. Docker is permitted strictly inside GitHub Actions `services:` (e.g., `amazon/dynamodb-local` for Layer 4 CI).
3. **Code-First OpenAPI 3.1 Contract:** Huma v2 is the single source of truth for `contracts/openapi.json`. The frontend consumes generated types via `openapi-typescript` + `openapi-fetch`. Never hand-write API request/response DTOs in TypeScript or bypass `apiClient` with raw `fetch()`.
4. **Canonical Units & Time:** Store temperatures canonically in Celsius (`temperature_c`) and humidity as percentage (`humidity_pct`, `0..100`). Store timestamps in UTC RFC 3339. Inject `Clock` for all time-dependent logic.
5. **Security & Auth:** Compare API keys using `crypto/subtle.ConstantTimeCompare`. Map domain errors consistently to RFC 9457 Problem Details (`application/problem+json`) via Huma error helpers. Never commit secrets, credentials, or `.env` files.
6. **Serverless Cost Discipline (Terraform):** Use DynamoDB On-Demand (`PAY_PER_REQUEST`), `arm64` `provided.al2023` Lambdas, SSM Parameter Store (Standard) instead of paid Secrets Manager secrets where appropriate, short CloudWatch log retention (14 days), and zero NAT Gateways.

## The 5 Testing Layers (Strict Separation)

| Layer | Gate | Scope | Real Dependencies | Tooling |
| :--- | :--- | :--- | :--- | :--- |
| **1. Unit** | PR | Pure domain rules, alert evaluation, formatters, UI hooks | None | Go `testing`, Vitest (`*.unit.test.ts(x)`) |
| **2. Component** | PR | Full HTTP API: routing, auth middleware, validation, status codes, RFC 9457 errors | None (in-memory fakes) | Go `humatest` / `httptest` (`*_component_test.go`) |
| **3. Contract** | PR | Zero OpenAPI/TS drift + runtime FE↔BE schema validation | None | `cmd/openapi`, `openapi-typescript`, Vitest + MSW + OpenAPI validator (`*.contract.test.ts(x)`) |
| **4. Integration** | PR | Real DynamoDB adapters, key conditions, range queries, conditional writes, TTL | `TEST_DYNAMODB_ENDPOINT` (`amazon/dynamodb-local` in CI) | Go `//go:build integration` + shared compliance suites |
| **5. E2E** | Deploy | Black-box business journeys against live deployed URL | Live environment (`E2E_BASE_URL`) | Playwright (semantic ARIA locators) |

## Verification Commands

Always run before finishing any task:

```bash
bash scripts/verify.sh
```

Once `justfile` is present, canonical developer commands are:
- `just generate-contract` — regenerate `contracts/openapi.json` and `frontend/src/api/schema.d.ts`
- `just pr-gate` — run lint + Layers 1–4 locally (Docker-free)
- `E2E_BASE_URL=<url> just test-e2e` — run Layer 5 against a deployed environment

## Testing Standards

1. **Bug fixes are test-first:** Reproduce with a failing test first, verify it fails for the expected reason, then apply the minimal fix.
2. **Fake-vs-Real Compliance:** Repository fakes (`internal/fake`) and DynamoDB stores (`internal/store/dynamodb`) MUST pass the same shared compliance test suites defined in `internal/domain`.
3. **Never weaken tests:** Never skip, delete, or relax assertions just to make CI green.
4. **Scope discipline:** Implement only what is requested by the scoped GitHub issue; do not refactor unrelated files.
